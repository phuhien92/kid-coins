Next.js 16 App Router

This project uses the App Router (not Pages Router). Everything in src/app/ is a Server Component by default. Add "use client" at the top when you need browser APIs, state, or Framer Motion.

Important: This is Next.js 16, which has breaking changes from prior versions. Before writing any framework-specific code, check node_modules/next/dist/docs/ for the current API. Don't rely on training data or StackOverflow answers for Next.js — check the local docs first.

Server vs Client — the decision rule

Use Server Component when…Use Client Component when…
Fetching data from DB/API on loadUsing useState or useEffect
Page that reads from Supabase on the serverUsing Framer Motion animations
Static or low-interactivity contentHandling user events (onClick, onChange)
Parent dashboard (data-first)Kid task list (tap interactions, optimistic updates)

Design System Rules You MUST Know

Rule 1 — No arbitrary bracket values. Ever.

// ❌ FORBIDDEN
<div className="bg-[#f3f4f6] p-[13px] w-[32vw]">

// ✅ CORRECT — use token classes
<div className="bg-cream-card p-lg w-full">

Rule 2 — Token classes only

Every color, spacing, radius, and shadow must map to a token in src/app/globals.css under @theme. The complete token list is in the Design Tokens reference sheet.

Rule 3 — No raw HTML for things the design system covers

// ❌ FORBIDDEN
<div className="flex flex-col">...</div>  // use <Page>
<div onClick={handler}>...</div>          // use <Button>
<div role="dialog">...</div>             // use <Modal>

Rule 4 — Interactive elements need all three states

// Every button/link needs hover, focus-visible, AND active
className="bg-green hover:bg-green-dk focus-visible:ring-green active:translate-y-1"

Rule 5 — More than 5 utility classes? Extract a component

If you find yourself writing 6+ Tailwind classes on one element, either use an existing primitive from src/components/ui/ or create a named sub-component.

KidContext — State for the Kid Shell

// src/context/KidContext.tsx
type KidSession = {
  kid: KidProfile;          // name, balance, avatarColor, familyId
  streak: number;           // current daily streak
  todayEarned: number;      // coins earned today
  goal: Goal & { current, target };
  tasks: Task[];
  addCoins: (delta: number) => void;  // optimistic update
}

Access it in any kid-shell component with useKid(). Narrower selectors exist for specific pages:

  • useKidHomeData() — home page shape
  • useKidTasksData() — tasks page shape

Current state: KidContext is backed by useMockKidSession() which returns hardcoded data. The comment in the file says "REPLACE WITH SUPABASE-BACKED IMPLEMENTATION." The public interface (useKid, addCoins, etc.) is stable — only the data source changes. This is the biggest pending task on the project.

import { useKid } from "@/context/KidContext";

export default function MyNewPage() {
  const { kid } = useKid();

  return (
    <Page>
      <Page.Header title="My Page" />
      <Page.Content>
        {/* your content here */}
      </Page.Content>
    </Page>
  );
}

Testing Rules

Every new module ships with a colocated test file:

New moduleTest file
MyComponent.tsxMyComponent.test.tsx (same dir)
useMyHook.tsuseMyHook.test.ts (same dir)
route.tsroute.test.ts (same dir)
  • Use Vitest + Testing Library (@testing-library/react)
  • Assert on user-visible output — not class names or internal state
  • Mock Supabase/Drizzle at the boundary — never hit the real DB in tests
  • Run with pnpm test:run

A test that only checks "it mounts without crashing" is not sufficient. Assert on something a user or caller would actually observe.

🧠 Retrieval Check

1. You want to add an animated coin counter to the kid home page. Should this be a Server Component or Client Component, and why?

Reveal answer
Client Component. The coin counter uses Framer Motion for animation and reads from KidContext (which uses useState). Both require a browser environment. Add "use client" at the top of the file. The parent page can remain a Server Component and render this as a child island.

2. A colleague submits a PR with this class string: className="bg-[#CFE7D8] p-[20px] rounded-[16px]". What's wrong and what's the fix?

Reveal answer
All three values use arbitrary bracket syntax — this is forbidden. The fix:
#CFE7D8 is --color-green-tint → use bg-green-tint
20px padding → use p-xl (or check the spacing scale in globals.css)
16px radius → use rounded-card
Fixed: className="bg-green-tint p-xl rounded-card"

3. You need a dropdown/select component for a parent settings page. What do you reach for first?

Reveal answer
Check src/components/ui/ first — if a Select component exists there, use it. If not, check Base UI (@base-ui-components/react/select) and wrap it with Earnie's design tokens. Never hand-roll focus trapping, keyboard navigation, or ARIA roles for interactive components that Base UI already covers.
